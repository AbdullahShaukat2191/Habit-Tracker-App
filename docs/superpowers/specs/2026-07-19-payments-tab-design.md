# Payments Tab — 2026-07-19

## Overview

Added a second-level tab to the existing `/projects` page: **Projects** (unchanged) and **Payments** (new) — a catalogue for tracking paid/client work: total amounts, what's been paid, what's remaining, milestones, and an automated payment ledger. No existing route, table, or behavior was modified; everything is additive.

## Data model

Three new tables (`electron/db/schema.ts` + raw DDL in `electron/db/migrate.ts`):

- **`payment_projects`** — entries shown in Payments → Projects. `sourceProjectId` is a nullable FK to `projects.id` (`ON DELETE SET NULL`), set only when the entry was imported from the main Projects tab. `name`/`color` are copied from the source project *at import time* — a snapshot, not a live join; renaming the source project later does not retroactively update the Payments entry. `totalAmount` and `developer` are edited independently in the Payments dashboard.
- **`payment_milestones`** — `title`, `description`, `amount`, `paid`, `paidAt`, belongs to a `payment_project`.
- **`payment_records`** — the ledger row behind Payment History. `milestoneId` is set when the record was auto-generated by toggling a milestone paid; `null` for ad-hoc "Add Payment" entries (which carry a free-text `note` instead).

`paidAmount`/`remaining` are never stored — derived client-side from `payment_records`, same pattern as existing task-count derivation on the Projects page.

Deleting a payment project cascades (in application code, not DB-level `ON DELETE CASCADE`, matching this codebase's existing style): records → milestones → project.

## Navigation

`src/app/projects/page.tsx` gained an outer tab bar (Projects | Payments) styled like the Tasks page's tab row. The "Projects" tab renders the pre-existing JSX subtree completely unchanged, nested under the conditional. "Payments" renders `PaymentsView`, which has its own inner tab bar (Projects | Payment History).

- **Payments → Projects**: grid of payment-project cards. "+ Add Project" opens `AddPaymentProjectModal`, which defaults to a create form (name/color/total/developer) and has an "Import from Projects" button — styled and positioned like the app's other "+ Add X" pill buttons — that switches to a checklist of not-yet-imported main-tab Projects for multi-select import. Clicking a card opens `PaymentProjectDashboardModal`: stat tiles (Total/Paid/Remaining/Milestones cleared), inline header edit, milestone list (add/edit/delete/toggle-paid), an "Add Payment" action for ad-hoc amounts, and a compact per-project payment list (manual entries deletable; milestone-sourced entries are managed via the milestone toggle only).
- **Payments → Payment History**: fully automated, read-only ledger across all payment-projects. Sort dropdown (Newest/Oldest/Projects) + Group toggle is a direct port of the Tasks page's sort/group mechanism (including localStorage persistence), applied to `payment_records` instead of tasks.

## Plumbing

`electron/db/queries/payments.ts` → registered in `electron/ipc/handlers.ts` under `paymentProjects:*`, `paymentMilestones:*`, `paymentRecords:*` → exposed via `electron/preload.ts` and `src/lib/ipc.ts` (and typed in `src/types/electron.d.ts`) → `src/lib/store/paymentStore.ts` (zustand, loads all three arrays fully like `projectStore`/`taskStore`) → components under `src/components/payments/`.

## Revision — same day: header restoration, full-width strips, full-page dashboard

Follow-up feedback after the initial build:

- **Header restored.** The outer Projects/Payments tab strip had replaced the page's normal title header (present on every other page — Current Tasks, Wish List, Long-Term Goals). Fixed by mirroring the Tasks page's exact header shape: `src/app/projects/page.tsx` now has one header block (title + conditional "+ Add Project" button, tab row beneath, italic tagline beneath that) where the `<h2>` text switches between "Projects" and "Payments" based on the active outer tab. `PaymentsView.tsx` nests the same pattern one level down — an `<h3>` subheading ("Projects" or "Payment History") above the inner tab row — so the structure repeats at both levels.
- **Cards → full-width strips.** `PaymentProjectCard.tsx` changed from a 2-column grid tile to a full-width horizontal strip: color bar, name, developer, a progress bar, and Total/Paid/Remaining/% shown inline. `PaymentProjectsTab.tsx` renders them in a single column instead of a grid.
- **Modal dashboard → full-page dashboard.** `PaymentProjectDashboardModal.tsx` was deleted and replaced by `PaymentProjectDashboard.tsx`, rendered in place of the project grid (via local `selectedProjectId` state in `PaymentProjectsTab`, not a route) when a strip is clicked. It fills the content area below the header/tabs, with a "← Back to Projects" link at the top instead of a close button.
- **Inline editing, no edit-mode toggle.** Name, developer, total amount, and color are directly click-to-edit on the dashboard (small `EditableText`/`EditableNumber`/`ColorDot` helpers — click text → input appears in place → Enter/blur commits, Escape cancels) rather than a separate "Edit" button that swapped in a whole form. Milestone/payment add-forms remain inline expanders (unchanged) — they were never modals to begin with.
- **Donut chart.** Per the dataviz skill's form guidance, a 2-slice "ratio against a total" is technically a meter's job, not a pie's — but a pie/donut was explicitly requested, so it was built deliberately: hand-rolled inline SVG (no charting library in the project), Paid in `--accent` and Remaining in `--text-tertiary` (an emphasis pairing, not full categorical — validated for CVD separation and contrast via the skill's validator; the muted color intentionally fails the categorical "chroma floor" check, which is expected for a de-emphasis gray), rounded end-caps, a 3px gap between segments, a center label (% paid), and a labeled legend with dollar amounts for both slices.

## Revision 2 — same day: explicit Edit button instead of click-to-edit

Click-to-edit-any-field (from Revision 1) turned out to be too easy to trigger by accident. Replaced with an explicit **Edit** (pencil icon) / **Delete** (trash icon, both `lucide-react`) button pair in the dashboard header, matching the icon-button pattern rather than plain text links. Clicking Edit swaps the identity block (name/color/developer/total) into the same form used by Revision 1's original modal-based edit mode — Cancel/Save buttons, no autosave-on-blur. Direct clicks on the name, total, or color no longer do anything; all header edits now require Edit → Save. The `EditableText`/`EditableNumber`/`ColorDot` inline-edit helpers were removed as dead code. Milestone/payment rows were untouched — they already required their own explicit Edit button, never supported click-to-edit.
